# ENG-3343 — M14 tenant-move rehearsal posture

Status: pending human ratification
Owner: Orvex Studio delivery-gate product owner
Decision: Recommended — do not relocate the shared live rehearsal tenant into
`eu9` on every PR. Use a disposable rehearsal tenant, or an explicitly
reversible move-and-restore fixture, before promoting the gate.
Recorded: 2026-09-08

## Rationale

`eu9` is an ephemeral, zero-endpoint target. Moving the shared rehearsal tenant
there on every pull request changes the tenant's live cell for the bearer mint,
isolation probe, and routing-core probe, so a failed or interrupted run can
leave later checks observing the wrong cell. The tenant's live registry value
is `eu1a`; this ticket's caller-side contract now reports target-cell refusals
and stale preconditions distinctly, but that typing does not make repeated
mutation of shared live state a safe default.

The recommendation preserves the purpose of AC6 while containing its blast
radius: the move path should still be exercised against a disposable fixture or
an owned transaction that restores the original binding before the run ends.
The `orvex-studio-lib` workflow and its exclusion remain untouched here because
they are owned by the sibling repository and the promotion is gated on an
observed whole-gate green.

## External follow-up

The named owner must ratify this posture and select the fixture strategy in the
ticket. That ratification, a deployed identity-pod diagnosis, and a live
`m14-gate-ci` run are not claims made by this repository record.
